# v2.0 Insight · Backlog institucional

- **Documento**: vivo — se actualiza en cada PR de D.2..D.7 que toque el dashboard.
- **Contrato firmado**: `docs/adr/015-genesis-v2-insight-y-cp-d2.md` §D2.
- **Creación**: 2026-08-14 (FASE D.2, commit inaugural).

## Propósito

El ADR-015 §D2 institucionaliza la separación entre criterios firmados
(en el ADR, inmutable) y lista concreta de features (aquí, viva). Este
documento clasifica cada feature del dashboard Genesis en las tres
secciones obligatorias que el ADR declara, y sirve de mapa de trabajo
para las sub-fases D.2..D.7 hasta el tag v2.0.

## Criterio de clasificación

Para efectos de admisión "fuera de orden", cuenta como **smoke test**
un test unitario o de componente que renderiza + ejecuta assertions y
corre en el job "Genesis Dashboard" del workflow `main CI` (`npm ci` +
`tsc -b --noEmit` + `vitest run`). Precedente: el run `31745541662`
cerró este pipeline con verde 5/5 al firmar ADR-015 — el mismo
pipeline es la autoridad que valida cada entrada de Sección 1.

## Sección 2 · Features aceptadas fuera de orden pendientes de validar

**Vacía al momento de creación del backlog.** Las 5 features del
dashboard aceptadas fuera de orden tienen todas smoke test corriendo
en el job "Genesis Dashboard" de CI (validado por run `31745541662`,
2026-08-13).

*Regla de mantenimiento*: cualquier feature admitida fuera de orden
en el futuro sin smoke test entra aquí y permanece hasta que tenga
uno. Es sección "congelador" — no debería crecer si la disciplina de
PR se mantiene. Si crece, es señal a atender, no estado normal.

## Sección 3 · Features aún no comenzadas

Cada entrada declara destino **v2.0** (blocker del tag) o **v2.1**
(mejora, no bloquea el tag).

### Auth básica del dashboard — v2.0 blocker (D.3)

- **Estado**: no existe. El dashboard hoy no tiene login.
- **Contrato**: ADR-015 §D2 criterio 1 — "existe autenticación real, no un placeholder abierto al mundo".
- **Mecanismo**: por decidir en su sub-fase D.3. Candidatos mencionados en el ADR-015: Discord OAuth, tokens firmados, otro. La decisión de mecanismo es del ADR de D.3, no de este backlog.
- **Destino**: v2.0 blocker.

### Deploy de genesis en `infra/docker-compose.prod.yml` — v2.0 blocker (D.4)

- **Estado**: `genesis/Dockerfile` + `genesis/nginx.conf` existen; el servicio NO está declarado en `infra/docker-compose.prod.yml`.
- **Contrato**: ADR-015 §D2 criterio 3 — "dashboard desplegado con evidencia runtime" + ADR-011 (runtime coincide con código).
- **Verificación de cierre**: `docker exec` sobre el contenedor genesis en prod + `curl` al bundle + `docker image inspect` con timestamp posterior al commit del tag.
- **Destino**: v2.0 blocker.

### Sección operacional de genesis en `docs/runbook.md` — v2.0 blocker (D.5)

- **Estado**: no existe.
- **Contrato**: ADR-015 §D2 criterio 4 — "mismo estándar que las secciones operacionales de `api`, `bot` e `infra` ya existentes".
- **Contenido mínimo**: cómo se arranca, cómo se apaga, cómo se ve un fallo desde afuera, cómo se rota su secreto principal.
- **Destino**: v2.0 blocker.

### Rutas dedicadas por feature (`/summary`, `/players`, `/activity`, ...) — v2.1

- **Estado**: `router.tsx` solo declara `/` (Home). Las 5 features renderizan como single-page-app.
- **Contrato**: NO está en los 5 criterios firmados del ADR-015 §D2.
- **Motivo v2.1**: mejora de UX (deep-link, back button, share URL), no bloqueo funcional. La navegación actual satisface la definición firmada "v2.0 es Insight funcional, no Insight pulido" (ADR-015 §Consecuencias).
- **Destino**: v2.1.

## Convención de mantenimiento

- Movimientos entre secciones (2→1 al validar, 3→1/2 al implementar) se hacen en el mismo PR que causa el movimiento.
- Cada entrada nueva debe llegar clasificada; PR sin clasificación se rebota (ADR-015 §D2 último párrafo).
- Este documento se lee de arriba a abajo — la estructura no cambia; solo el contenido de secciones.
- Referencia autoritativa de qué convierte una feature en "lista para tag v2.0": los 5 criterios firmados en ADR-015 §D2. Este backlog no los redefine, solo los aplica.
